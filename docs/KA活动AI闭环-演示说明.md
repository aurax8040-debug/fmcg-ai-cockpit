# KA活动AI经营闭环演示说明

## 作品定位

这是一个面试用、本机运行的高保真 Demo，场景是佳沛经销商向 KA 商超供货后的活动经营闭环：NKA 客户经理对接商超总部，总部确认活动后提报营销部，营销部协调执行公司与长临促，战区销售巡店跟进，门店 POS 数据回流到 BI。

主流程只有一条：**数据底座 → AI研判 → 业务执行 → AI经营分析**。

## 数据真值

- `真实样例`：`NKA商超.xlsx` 的客户/月销售与毛利聚合。
- `匿名模拟`：KA-A、12 家门店、活动计划、POS、模拟成本、长临促/路演费用、第三方执行证据。
- `AI 推断`：Dify 工作流生成的事实整理、数据缺口、待验证假设、核查建议与经营摘要。

真实 BI API、库存、SFA 下发、人员信息、真实活动成本和业务影响均未接入。

## 启动

1. 启动本地 Dify，并登录后导入 `dify/ka-activity-analysis.yml`。
2. 发布工作流并把 API 密钥仅保存到未跟踪的 `.env.demo`。
3. 运行 `./scripts/demo-stack.sh up`。如果暂时没有 Dify 密钥，也可用 Node 22 直接运行 `server/start.mjs`；此时确定性数据和任务闭环可用，点击研判会明确显示“Dify尚未配置”。
4. 打开 `http://127.0.0.1:58044/preview/p1/index.html`。

## 3—5 分钟讲解脚本

1. **经营总览**：先看重点活动、POS覆盖、执行证据覆盖和活动贡献观察。强调“活动贡献观察”来自匿名模拟口径。
2. **数据底座**：说明统一关联键 `KA → 活动 → 门店 → 日期 → SKU`；展示数据来源、更新时间和完整度门槛。无库存数据时不判断缺货。
3. **AI研判**：经营数字由后端代码计算，Dify 只读取当前活动的证据 JSON。结果分成已知事实、数据缺口、待验证假设、建议核查和边界，每项引用 `trace_id`。模型失败时保留确定性指标，不展示模板结论。
4. **业务执行**：AI 建议必须由人确认后才能创建任务。依次演示草稿、已确认、执行中、待补证、已完成，再补一条匿名模拟证据。
5. **AI经营分析**：展示前中后销售、模拟毛利、可归属费用、贡献观察、证据覆盖和任务闭环。没有有效对照时只能说“变化观察”，不能说“活动增量”。

## 生产替换路径

保持页面和 Dify 输入/输出契约不变，将 Mock BI 服务内的数据读取替换为佳农 BI/数仓的服务账号查询；再把本地 JSON 任务状态替换成 SFA/CRM 的任务 API 与对象存储证据。模型仍不直连生产数据库，Dify 密钥仍只保存在服务端。

## 守护规则

- POS 覆盖低于 80%：阻断经营假设，只生成补数动作。
- 80%—95%：允许有限研判，结论必须标记待验证。
- 缺模拟成本：只阻断活动毛利/贡献，不阻断销售观察。
- 缺执行证据：只阻断执行质量判断。
- 引用未知 `trace_id`、输出缺字段或不是合法 JSON：拒绝整个 AI 结果。
- AI 不自动下任务、不审批费用、不调整营销资源。
