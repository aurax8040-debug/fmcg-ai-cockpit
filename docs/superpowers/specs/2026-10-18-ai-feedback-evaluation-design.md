# AI反馈与评测闭环设计

## 目标

为驾驶舱AI回答增加可追溯反馈，形成可用于产品迭代和简历佐证的真实口径：采纳、修改后采纳、否决、任务创建、任务完成、失败原因与响应时间。同时建立30条冻结评测样本，验证事实、证据、边界和失败兜底。

## 关键边界

- 真实使用记录与冻结评测结果分开，测试样本不得冒充真实用户使用。
- 每条成功回答只能保存一个当前决策，允许后续修正并保留更新时间。
- 修改后采纳和否决必须填写原因；直接采纳可选填备注。
- 任务创建与完成由既有人工任务流程回写，不能因打开弹窗就计为创建。
- 调用失败自动进入失败样本，不纳入建议采纳率分母，但纳入需复盘样本。
- 所有指标显示样本量；少于20条已评价回答时标记“样本积累中”，不可写入简历成果。

## 数据模型

驾驶舱运行记录新增：`duration_ms`、`feedback`、`task`。反馈含`decision`、`reason_code`、`note`、`updated_at`；任务含`created_at`、`completed_at`和本地任务ID。

## 指标口径

- 建议采纳率 =（直接采纳＋修改后采纳）/ 已评价成功回答。
- 任务创建率 = 已创建任务的采纳回答 / 已采纳回答。
- 任务闭环率 = 已完成任务 / 已创建任务。
- 需复盘样本 = 修改后采纳＋否决＋调用失败。
- 平均响应时间 = 有耗时记录的全部成功/失败调用耗时均值。

## 页面

每条AI回答下方提供“采纳”“修改后采纳”“否决”按钮，后两者要求填写原因。驾驶舱底部增加“AI效果验证”卡，展示样本量、采纳率、任务闭环率、需复盘样本和平均响应时间，并明确真实使用与冻结评测的区别。

## 冻结评测集

30条样本覆盖：经营事实问答、证据不足、禁止越权、时间口径、任务建议和服务失败。每条包含问题、类型、必须出现的要点和禁止出现的断言。第一阶段交付样本及自动结构检查；真实Dify批量运行产生单独结果文件，不预填通过率。
