# 活动门店智能巡检 Agent MVP 设计

## 目标

在现有 AI 经营驾驶舱内增加一个可演示的核心场景：每天从活动门店中识别“POS 表现不及预期且执行存在异常”的门店，跨勤策 TPM/SFA、促销员填报、佳农 ERP、客户 POS 和受控商圈数据归纳证据，给出核查优先级和整改建议，并进入人工任务闭环。

## 产品边界

- 保留现有经营驾驶舱、AI 对话、任务与评测功能，不新增一级页面。
- 数据使用匿名模拟样例，页面明确标识，不冒充生产数据。
- BI/规则计算 POS 差距、有效在岗率、陈列、价格、SKU 和质量异常；模型不重算指标。
- Agent 只能动态选择获批的只读工具；无库存工具，不判断缺货。
- 竞品活动来自受控商圈数据，不使用无来源的模型常识。
- 任务仅生成待人工确认草稿，不自动下发、调人或追加预算。

## MVP 页面

将右侧“经营异常核查”替换为“活动门店智能巡检”。首卡展示最高优先级门店：

- POS 活动期相对历史基线变化；
- 促销员有效在岗率与长期离岗；
- 陈列位置/面积、活动 SKU、价格、果品质量；
- 历史活动执行表现与周边竞品活动；
- 已知事实、待验证因素、建议动作和数据来源。

提供“AI 深度研判”和“生成整改任务（人工确认）”。AI 研判展示实际调用的只读工具、管理结论与证据边界。

## 数据与规则

新增匿名模拟：ERP 供货、促销员班次、SFA 巡店、陈列检查、果品质量、门店历史活动、受控商圈事件。统一关联键为 `activity_id + store_id + date + sku_id`。

优先级分数仅用于排序：POS 低于基线、有效在岗不足、长期离岗、陈列降级、SKU 缺失、价格偏差、果品质量异常、竞品活动分别贡献风险分；页面显示构成，不把相关性表述为因果。

## 验收

- A10 门店因 POS 下降、有效在岗不足和陈列降级排在首位。
- Agent 面对“为什么 A10 POS 不及预期”至少调用 POS、促销员、SFA/陈列、商品质量、历史和商圈工具。
- 页面明确显示数据来自匿名模拟及勤策分模块＋ERP/POS。
- 任务需人工确认；库存、因果和自动资源动作边界保留。
- 原有测试和 AI 效果验证继续工作。
