# 用这个项目学版本管理

## 第1课：先看清你在哪
主目录是本README所在目录；不要在用户根目录或多个产品总目录执行git add .。
`git status`看有没有未存档改动；`git branch --show-current`看当前修改路线；`git log --oneline -5`看最近存档。

## 第2课：四个名词
仓库是项目历史档案；commit是本机存档；branch是修改路线；push是把本机存档同步GitHub。未推送的提交不算云端备份。
.gitignore是不要纳入存档的清单，不是秘密加密工具；已经提交过的秘密需要撤销/轮换，不能只加忽略规则。

## 第3课：下次改一个按钮时照着做
先在本项目目录执行 `git status`。确认干净后执行 `git switch -c codex/button-copy`。
让Codex只改这个按钮。执行 `git diff`看改了什么；运行相关测试。
用 `git add 具体文件`选择要保存的文件，再用 `git diff --cached`检查本次存档。
用 `git commit -m "调整首页按钮文案"`保存；用 `git push -u origin codex/button-copy`同步。
在GitHub比较该分支和main，检查后合并。回到本机用 `git switch main`、`git pull --ff-only`更新。
先学这条流程，不必一开始掌握rebase、cherry-pick或复杂团队分支。

## 第4课：如何找回
未提交的修改先请Codex保存或导出差异，不直接清空。
撤销已提交的单次改动用 `git revert 提交编号`，生成一个新的反向提交，并保留历史。
只想看基线，在另一个空目录用 `git clone 仓库地址 恢复演练`，然后 `git -C 恢复演练 switch --detach baseline-2026-10-25`。不要覆盖当前工作目录。
恢复源码不恢复浏览器localStorage、Dify数据库/密钥。它们需要另外导出备份。

## 给Codex的固定说法
“先告诉我项目目录、分支和是否有未提交修改；为本次需求开分支，只修改这一项。完成后看差异、验证并提交，告诉我提交编号，以及是否已同步GitHub。涉及删除历史、覆盖未提交改动或公开仓库时先说明。”
