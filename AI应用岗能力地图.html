搞清楚「AI 应用产品要不要训练数据」，以及「什么时候上 Prompt / RAG / 微调」——这是 AI 应用产品经理的核心判断力。
AI 价值链分层 三条技术路线 面试话术

一、AI 价值链三层：你在哪一层

「需不需要训练数据」不取决于大厂小厂，而取决于你在价值链的哪一层：

1
基座模型层 —— OpenAI / DeepSeek / 通义等。需要海量训练数据。岗位：算法研究员、训练工程师。
2
应用 / 策略层（你在这里） —— 业务产品团队，通常不自己训练，用现成模型做场景落地。岗位：AI 产品经理、应用策略。→ 核心资产是「评测数据」，不是「训练数据」。
3
落地 / 运营层 —— 一线业务，不需要训练数据。岗位：运营、销售。

二、三条技术路线：什么时候用什么

「没有训练数据」≠「技术路线上没有选择」。AI 应用层有三条路线，判断力就在这里体现：

Prompt
零训练：写提示词 + 契约 + 护栏，直接调现成模型。（你现在的作品）
适用：通用能力够、场景靠约束就能落地。优点快、成本低；缺点是能力边界受限于模型。
RAG
零训练、但要数据：把企业私有数据做成检索库喂给模型当上下文。
适用：需要注入专有知识、但又不想/不需要训练。需要的是知识库数据，不是标注训练集。
微调
要训练数据：用少量标注数据微调，让模型学会特定格式或领域。
适用：Prompt 和 RAG 都搞不定的稳定格式/领域任务。到这一步才真正需要标注训练数据。

判断顺序：先 Prompt → 不够再 RAG → 仍不够才微调。绝大多数应用产品停在 Prompt + RAG。

三、高频追问 & 你的答法

Q1：你不训练模型，凭什么保证输出对？
A：经营数字是代码确定性计算的，模型不碰数字，只做归纳和引用；输出逐条引用 trace_id，引用越界就整体拒绝——把「可错的部分」关进工程笼子。
Q2：提示词会漂移，怎么做回归？
A：30 条冻结评测样本（不随版本改）+ 15 个确定性单测（mock 掉模型测规则），这就是应用层的「测试集 + 验证集」。
Q3：怎么证明产品真的有用？
A：线上人工反馈闭环——采纳率、任务生成率、任务完成率，≥20 条样本才出指标，衡量真实价值而非离线分数。
Q4：这个产品需不需要训练数据？
A：当前基于现成大模型 + 提示词 + 契约，不需要。若后续遇到提示词搞不定的专有场景，再考虑微调或 RAG，那时才需要标注数据或知识库。

四、一句定心话术（可直接背）

「AI 应用产品通常不需要自己训练模型。我的做法是基于现成大模型，用提示词 + 输出契约约束行为，把重点放在评测集和反馈闭环上。如果后续出现提示词搞不定的专有场景，再考虑微调或 RAG，到那时才需要准备标注数据或企业知识库。所以我的核心资产是『评测数据』，不是『训练数据』——这恰恰是 AI 应用产品经理真正该掌控的东西。」
