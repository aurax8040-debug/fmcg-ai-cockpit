# 快消智析 · ChatBI 经营分析平台

> **AI 产品经理作品 · 企业级 ChatBI**：不是给 BI 加一个聊天框，而是把企业最痛的经营问题封装成「开箱即用的场景 skill」，业务人员点开即用，直接得到「归因 + 证据 + 建议」。快消 KA 场景验证，能力通用、可复用到任意行业。

**在线演示**：本地运行见下文；Demo 为受控 LLM 应用，遵循「**BI 算数、AI 判数、人来定夺**」的边界原则。

---

## 一、这个项目解决什么问题

快消企业 ERP、POS、SFA、DMS 等系统数据分散，传统 BI 依赖人工逐层钻取分析，存在三大痛点：

| 痛点 | 传统做法 | 本方案 |
|---|---|---|
| 经营异常难定位 | 人工逐层看报表 | AI 自动筛查异常客户/门店，给出证据与建议 |
| 优秀经验难复用 | 靠人传人 | 跨区域案例检索，AI 提炼可借鉴打法 |
| 复盘成本高 | 单次 2 小时 | AI 生成复盘草稿，单次降至约 1 分钟 |

## 二、核心设计理念

**BI 算数、AI 判数、人来定夺** —— 明确划分三者的职责边界：

- **BI（Workflow）**：确定性计算。采购、价格测算、预算达成率等口径明确的逻辑，用确定性 Workflow 完成，不做「为用 AI 而用 AI」。
- **AI（Agent）**：动态研判。预算归因、跨区域案例借鉴、异常原因调查等需动态判断的任务，交给 Agent。
- **人（决策）**：AI 只给建议与证据，保留业务方决策权，形成「AI 建议 → 人工确认 → 指派下发 → 执行回填」的闭环。

## 三、技术架构

```
总控 Agent（意图识别 + 路由）
   ├── 子 Agent ×N（业务研判：预算归因 / 异常原因 / 案例借鉴）
   ├── Workflow（确定性计算：价格测算 / 采购 / 预算达成）
   └── Checker（代码级校验层，防幻觉）
```

关键设计：

- **防幻觉（核心亮点）**：代码级 Checker 校验层，对模型输出数字自动比对，误差超 1% 即回退；输出严格区分「事实 / 推测」。
- **权限兜底**：针对权限冲突设计纵向拦截，低置信度降级 + Human-in-the-loop 人工确认闭环。
- **技术栈**：多 Agent 编排（LLM：ChatGPT / DeepSeek）、RAG 检索增强、Dify 工作流、Node.js 22 + 原生 ECharts 前端。

## 四、六大经营场景（= 开箱即用的场景 skill）

区别于「给个聊天框让用户自己问」，本方案把企业最痛的六个经营问题**封装成六个开箱即用的场景 skill**——业务人员无需懂数据分析、无需组织 prompt，点开即得「归因 + 证据 + 建议」。

| 场景 skill | 用户开箱即用能得到 | 对应角色 |
|---|---|---|
| **预算诊断** | 谁没达标、缺口多少、为什么（下钻归因） | 管理层 |
| **SKU 增长** | 哪个 SKU 有增长机会、机会在哪 | 一线业务 |
| **价格异常** | 哪些门店价格异常、异常在哪个环节 | 一线业务 |
| **供应链短缺** | 物料缺口在哪、影响多少需求 | 管理层 |
| **需求测算** | 采购/需求量的测算建议 | 一线业务 |
| **政策知识库问答** | 直接问政策，RAG 检索作答，不用翻文档 | 全员 |

每个场景 skill 背后预设好了：数据口径（查哪张表、哪个指标）、分析逻辑（如何归因、如何对标）、Agent/Workflow 分工、证据组织与建议输出。

### 案例：预算诊断的「为什么」是怎么算出来的

面试高频追问：AI 说的「客户 B 没达标」这个归因可信吗？答案分两步：

**第一步 · 确定性计算（Workflow，纯算术，不经过 LLM）**：从整体下钻到局部，精确锁定缺口来源。

```
整体预算达成率 82%（未达标）
  ├─ 客户 A 达成 95% → 达标，排除
  ├─ 客户 B 达成 60% → 锁定拖后腿客户
  │    ├─ 门店 1 达成 50% → 主因
  │    └─ 门店 2 达成 70%
  │         └─ SKU-X 铺货不足 → 根因
  └─ 客户 C 达成 88%
```

「缺口多少、在哪一层」是纯数据对比算出来的**事实**，不依赖 AI。

**第二步 · AI 研判（Agent，标清推测）**：基于下钻结果，AI 结合业务知识解释「为什么缺口大」（铺货未进 / 促销未跟 / 竞品抢占），并明确标注这是**推测**、附证据、给建议。

**Checker 兜底**：AI 输出的任何数字，Checker 与 Workflow 算的真值自动比对，误差超 1% 即回退——保证 AI 说的数字准确，只有「为什么」的判断是 AI 生成的。

## 五、量化成果

**数据底座（全量）**：打通 ERP / POS / SFA / DMS / 电商五大业务域，覆盖 3800+ 门店、13 个 KA、325 个 SKU（盒马、永辉、大润发、沃尔玛、华润等）。

**AI 试点（验证）**：

| 指标 | 结果 |
|---|---|
| 试点覆盖门店 | 200 家 |
| 试点分析准确率 | 85% |
| 建议采纳率 | 92% |
| 单次复盘耗时 | 2 小时 → 约 1 分钟 |
| 核心数据覆盖率 | 97%（推动 10 张经营看板） |

## 七、运行与配置

**环境**：Node.js 22。

```bash
# 静态预览
node scripts/static-preview.mjs

# 运行测试（使用模拟服务，不消耗真实模型额度）
node --test tests/*.test.mjs
```

密钥仅存本机 `.env.demo`，不入库；`.env.demo.example` 为空值模板。Dify 与 Docker 按本机配置准备。

## 八、数据与边界说明

- `demo-data/` 下数据为 `MOCK_TEST_FIXTURE` 测试夹具，**非真实预算 / 销售口径**，仅用于演示与测试。
- Demo 权限边界：接口使用请求中模拟用户与授权门店做范围校验，未接入真实登录鉴权，不代表生产级 RBAC。
- `dify/` 中 DSL 为代码导出版本，不保证等于当前 Dify 线上配置。
